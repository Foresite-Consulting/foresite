# Changelog

Plain-language notes first, then the technical detail. Dates as `18 Oct 2026`.

## Unreleased

### For the client

- The app shell exists: a dashboard of key numbers (demo data only), installable on a phone, with an offline page that shows the last numbers it had and when they were updated.
- Every number now belongs to a trading day that runs from opening to close, past midnight: Saturday night's 1 am sales count on Saturday. Days are correct on the nights the clocks change, for venues outside WA.
- Every forecast now comes with a likely range and its accuracy to date, for example "In the likely range 57 of 70 times in the last 10 weeks. Typical error 8% (a week ahead).". Forecasts are estimates, not guarantees.
- A simple, explainable benchmark forecast (same weekday last year, adjusted for recent trend) that any smarter model has to beat before Phase 2 sign-off, and that takes over automatically, with an alert, if the smarter model is worse four weeks running.
- People counters at the door can now send their counts to the app: people in and out every few minutes, kept once even when a counter re-sends after losing its connection. Nothing shows on screen yet.

### Fixed (scaffold review)

- Keyboard focus is now visible everywhere: a 2px outline in the theme's `link` colour. `theme:check` requires `link` to reach 3:1 on `bg` and `surface` for the focus indicator. (#1)
- `formatAud` and `formatPercent` round halves away from zero correctly (`1.005` → `$1.01`, `-2.675` → `-$2.68`); new `formatAudCents` formats integer cents exactly. Money should flow as integer cents. Added `ES2023.Intl` to the TypeScript libs for `signDisplay: 'negative'` and decimal-string formatting. (#2)
- `Permissions-Policy` no longer lists `bluetooth` and `interest-cohort`, which Chromium rejects with a console warning. The smoke tests now fail on console warnings as well as errors. (#3)
- `/theme-assets/*` responses carry their own locked-down CSP (`default-src 'none'; style-src 'unsafe-inline'; sandbox`), `nosniff` and `Cross-Origin-Resource-Policy: same-origin`. Theme asset names are validated at load time (file in the theme folder, `.png`/`.svg`/`.ico`/`.webp` only). (#4, #8)
- Theme `client.icons` is now a list of `{ src, sizes, purpose? }`. The manifest uses the declared sizes and purpose and takes the MIME type from the extension, instead of guessing from file names. Both themes migrated; the old string list is rejected with a clear message. (#9)
- Service worker (cache `v2`): static files from an old build are dropped when the offline page changes, and the static cache is capped at 60 entries. `/offline` is stored only if it is a 200 HTML document at exactly `/offline`, never a redirect target; `docs/pwa-offline.md` notes it must stay public and free of personal data. (#5, #6, #8)
- The offline snapshot is only written for demo numbers until the auth PR decides retention, and is read back strictly (at most 24 tiles, 200 characters per string, valid date and timezone). (#7)
- More tests: `NEXT_PUBLIC_THEME` (valid slug, empty, `../etc`), the font fallback warning (now once per family), axe on `/offline` with and without a saved snapshot, and the default colour scheme per Playwright project. (#8)

### Review follow-ups (PR 2)

- Venue `timeZone` must be a canonical IANA name: links such as `Australia/NSW` are rejected with the canonical zone in the message (no longer silently accepted), as are `UTC`, `GMT`, `EST`, `Etc/…` and fixed offsets.
- A `special_hours` exception with `hours: {}` is rejected; it must list at least one section.
- Data dictionary: GST is rounded per row; aggregate GST is the sum of row `gst_cents`, never recomputed from aggregate net.
- `toCsv` guards against formula injection: text cells starting with `=`, `+`, `-`, `@`, tab or CR get a leading `'`. The committed fixture is unchanged byte for byte.
- `npm run synth` refuses to overwrite a folder holding a different dataset (by `manifest.json`) unless `--force`.
- Synth CLI warns on stderr when a run goes past the last listed sample public holiday.
- Interval-list cache limited to 2,000 entries per venue (other memo maps stay at 20,000).
- Removed the unused `formatLocal`; interval labels have one implementation (`buckets.ts`).
- Golden vectors for a Sydney 02:30 cut-over on both change nights (1410 + 1410 minutes in spring, 1440 + 1500 in autumn), cross-checked with Python `zoneinfo`.
- Data dictionary: an open before the cut-over is on the next calendar date; day lengths with a cut-over in the change band.
- Instants: `InstantInput` is now `Date | string`; numbers are rejected by the type and at runtime (epoch seconds could pass as milliseconds). New `fromEpochMs(ms)` for explicit conversion. ISO strings with a bracketed annotation (`[...]`) are rejected.

### Review follow-ups (PR 4)

- Once the forecast model has been switched back to the simple baseline, it now stays switched back in later weeks, even if a week looks good again, until a person re-checks it against the Phase 2 test. A model that stays worse no longer raises a fresh alert every week.
- Forecast engine (`forecast/`):
  - Untracked `forecast/.coverage` (already in `.gitignore`).
  - Scoring: "only the latest issue counts" now applies before rows without a point are dropped, so a later `unforecastable` re-issue retires the earlier point. Decision 5 in ADR 0004, for Lachlan.
  - Rollback is enforced as one-way: `decide_rollback(..., state=)` with `RollbackRecord`s, `reinstate()` only on a passing gate, `evaluate --state <file>` (atomic, locked) and `--reinstate --sign-off`. `alert_id` is a hash of venue, metric, challenger id + version and the trigger week, stable across re-runs and later weeks; alerts carry `new`, `trigger_week_start` and `challenger_model_version`; decisions carry `weekly_verdict` and `rollback_record`.
  - Training window: optional `training_end` column in the forecast log (`<= as_of`; blank for the baseline). The gate refuses hold-out forecasts with `training_end` on or after their target week's Monday; `evaluate --sign-off` requires it on every challenger row. `synthetic-challenger --training-end`.
  - Files: input size checked with `stat()` before reading; writes flush and `fsync` the temporary file before the rename and `fsync` the folder; forecast-log appends take an `fcntl.flock` advisory lock on `<log>.lock` (one writer per log until Postgres); `accuracy --out-dir` and `evaluate --alerts-out` are atomic and refuse to overwrite an input.
  - New boundary tests: trend window `as_of − 55` in, `as_of − 56` out; holiday tie-break inside 330-400 days; match fraction at 9 of 10, 10 of 11 and 7 of 8.
